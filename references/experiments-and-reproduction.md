# 实验、软件与复现

## 用实验检验主张

先列主张，再找对应实验。不把精度、速度、稳定性、可扩展性和物理合理性当作同一种证据。

| 主张 | 有说服力的证据 | 需要追问 |
|---|---|---|
| 收敛阶/误差阶 | 在声明的范数和参数区间内做网格、时间步或迭代收敛分析 | 参考解是否充分准确？是否被其他误差掩盖？ |
| 时间更少 | 同精度、同任务的端到端时间，含必要设置 | 是否只计内核？是否换硬件或放宽精度？ |
| 内存更少 | 实际峰值或可信存储分析，含工作区和复制 | 是总内存还是每进程？使用更多节点了吗？ |
| 通信更少 | 明确定义的消息/字节/轮数和目标精度 | 是每步减少还是求解总量减少？ |
| 可扩展 | 强/弱扩展曲线、规模与 p、基线和计时范围 | 算法迭代数、通信、负载是否变化？ |
| 新机制有效 | 去除该机制的消融或有解释力的对照 | 是否同时改变调参、精度或硬件？ |
| 更鲁棒 | 病态/边界/不同初值与参数测试、失败率 | 失败和 timeout 是否被剔除？ |
| 科学结果可靠 | 解析解、守恒量、高精度参考或独立方法验证 | 物理模型误差与数值算法误差能否区分？ |

确定性求解器也可有计时波动；随机算法和采样方法还要区分随机初始化、样本变化与测量噪声。检查重复次数、均值/中位数、标准差/标准误/置信区间的定义及失败处理。不能看到误差棒就断言统计显著。

## 比较的最低条件

记录问题实例、目标误差或可行性、停止条件、参考解、初始化、超参数选择、精度格式、软件版本、编译选项、BLAS/MPI/加速库、CPU/GPU/节点与互连、线程/进程布局、预热与计时范围。

基线需要同时考虑：直接前作、实际常用方案、同类最佳已知方法。某篇文章可能只比较其中一种；据实说明，不要求每项都重新实现。理论上比较最优前作时要统一假设、oracle 与精度；工程上比较“相同算法换实现”和“不同算法同任务”时分别标注。

不要把论文中未使用的最新基线追认为当年的遗漏。若用户关心当前选型，可以另行检索更新方法，并区分发表时贡献与当前竞争力。

### 图表读数

逐个解释关键图表：横纵轴、单位、线性/对数坐标、误差棒、归一化、比较对象、支持的结论及不支持的外推。只有图像读数时用约数并说明估读；复杂度斜率不足以证明理论界。

汇总 benchmark 时保留 timeout、未收敛、OOM 与失败分母。performance profile 和平均加速比的结论取决于成功判据、实例集合与归一化；不要对不同实例的单一最好结果作无条件排名。

## JCTC 与物理模拟附加项

按实际方法选用，而非机械填写所有项目：

- 体系、几何、粒子/电子/基函数数、电荷、自旋、边界、基组/截断、赝势、k 点、泛函或势函数；确定“规模 N”具体代表什么。
- SCF、线性求解、几何优化、能量/力阈值；比较能量时检查单位和归一化。能量精度不能直接替代力或应力精度。
- 有限尺寸、有限温度、基组不完备、截断与时间步误差；新增数值加速是否改变物理近似？
- 动力学/采样的时间步、平衡化、轨迹长度、系综、thermostat、相关性、有效样本数与误差估计。
- 化学精度或应用可接受阈值必须说明所针对的观测量与任务，不设跨领域通用阈值。
- 对方法声称的适用范围检查是否只测小体系、单类化学体系或特殊谱隙。线性/低阶标度可能依赖局域性、稀疏性、精度及维数，不能脱离条件使用。

## CPC 与软件论文附加项

若有 Program Summary，抽取问题、求解方法、语言、版本、许可证、依赖、程序/数据位置、限制和运行需求。再读长文里的数学方法、架构、数据结构、使用示例、验证及性能。

区分三类贡献：新数学算法、已有方法的高效实现、可复用的框架/接口与能力扩展。软件没有新的收敛定理仍可有明确贡献；引用成熟算法也不自动证明软件实现正确。

核查开源链接是否可访问、论文对应 commit/release 是否可定位、示例是否包含原始输入与参考输出。仓库存在不等于本文结果可复现，当前 main 分支也不一定对应发表版本。

## 复现规划与执行状态

用户要复现规划时形成以下记录；未要求执行时不把计划写成已完成：

| 对象 | 应记录 |
|---|---|
| 目标 | 对应定理/图/表/功能，判定误差与成功准则 |
| 输入 | 数据、网格、分子结构、随机种子、参数和获取位置 |
| 实现 | release/commit、语言、库、编译选项、算法变体 |
| 环境 | CPU/GPU、精度、内存、节点、进程线程、互连 |
| 路径 | 公式 → 算法步骤 → 源码函数/文件 → 运行命令 → 输出 |
| 资源 | 小规模校验与目标规模各需的内存、时间或未知量 |
| 比较 | 原文指标、容差、统计口径、失败标准 |
| 状态 | 仅查材料 / 可执行条件齐备 / 已运行哪些命令 / 哪些结果匹配 / 哪些尚未验证 |

执行通常先用解析解、制造解、小矩阵或明确参考结果验证正确性，再测收敛与固定精度性能，最后按预算扩规模。选择与方法相关的边界案例，不机械添加无意义测试。

完整论文与代码不一致时保留两套版本的定位。可以提出一种合理解释或实现选择，但不得静默“修正作者算法”，更不得把修正后结果当作复现原算法。

报告复现限制的具体原因，例如缺少输入、专用硬件、许可证依赖或目标运行尚未完成；不要用“可复现”一个词掩盖不同验证深度。

这些检查吸收了科学计算的复现要求及 NeurIPS 对理论、实验、统计和计算资源的分项检查思路；按贡献选择适用项。[SISC 作者说明](https://epubs.siam.org/journal/sisc/instructions-for-authors)、[NeurIPS checklist](https://neurips.cc/public/guides/PaperChecklist)。
